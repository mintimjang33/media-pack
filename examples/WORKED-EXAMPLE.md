`examples/progressive-lens.flow.json` 이 실제로 만든 편입니다.
**「터널 입구가 안쪽보다 80배 밝은 이유」** · 95.17초 · 1080×1920 · 2026-09-04 제작.

| 총 소요 | 이미지 ~12분 + 클립 ~5분 (자동, 대기 포함) |
| 최종 영상 | 95.17초 · 82MB · −14.5 LUFS |

**하루치 무료 크레딧(50) 안에서 한 편이 끝납니다.**


**이 팩이 담당하는 건 ④뿐입니다.** ⑤는 별도 레인이라 팩에 넣지 않았습니다(README 참조).

## 클립을 7개로 줄이는 방법

95초에 클립 7개(28초)면 3분의 1도 안 됩니다. 나머지는 **정지 이미지 + 카메라 무빙**으로 갑니다.
클립을 쓸 자리는 이렇게 골랐습니다.

| 쓴다 | 안 쓴다 |
|---|---|
| 훅 첫 컷 (첫인상) | 수치를 읽는 컷 — 그래프·치수선이 주인공이라 배경은 정지여도 된다 |
| 문제를 몸으로 보여주는 컷 | 라벨만 바뀌는 연속 컷 — 같은 이미지에 오버레이만 갈아 쓴다 |
| 실패 상태 | 상하 분할 비교 — 두 정지 이미지를 병치하는 게 더 명확하다 |
| 발상 전환의 시각 증명 | 짧은 전환 컷(1.5~2.5초) — 텍스트가 다 나오기도 전에 끝난다 |
| 클로징 롱샷 (수미상관) | |

정지 이미지도 `scale 1.0 → 1.08` 정도의 느린 카메라를 걸면 멈춘 느낌이 안 납니다.

## 룩 통일이 실제로 되나

됩니다. 14장이 **같은 터널·같은 날**로 읽힙니다 — 앵커 1장을 참조로 물린 결과입니다.
다만 두 가지를 겪었습니다.

1. **참조가 연쇄된다.** Flow 자동 제목이 다 비슷하면(`Expressway tunnel …`) 앵커가 아니라
   직전 이미지를 물어옵니다. 룩은 유지되지만 앵커에서 서서히 멀어집니다.
   이 팩은 이미지별 제목을 **전체 문자열로** 기억해 그 문제를 막습니다.
2. **한 장이 깨졌습니다.** `walls close on both sides`를 모델이 전경 벽으로 그려 화면 40%를
   막았습니다. 프롬프트를 고쳐 다시 뽑았고 — **이미지는 0크레딧이니 부담이 없습니다.**

## 클립이 제대로 붙었는지 확인하는 방법

라벨만 바꾸고 자산은 그대로인 사고가 흔합니다. 렌더 결과에서 프레임을 뽑아
**원본 클립의 같은 시점 프레임과 상관계수**를 재면 확실합니다.

```python
# 완성본 t=cut.s+d/2 프레임 ↔ 원본 클립 t=clipFrom+d/2 프레임, 상단 60%만 비교
# (하단은 자막·라벨이 덮는다). 실측 7/7 · 0.82~1.00
```

낮게 나오는 건 카메라가 움직인 탓입니다. 0.8 미만이면 자산이 어긋난 것으로 보세요.
