## STEP 1 — 소재 게이트 ★여기서 걸러야 한다

벤치마크가 **36편을 태워** 증명한 실패 포맷이 있다 (중앙값 3.1만 vs 58만, **18.7배**).
**소재 선정이 성패의 대부분이다.**

### 통과 3조건 (전부 만족)

| # | 조건 | 확인 질문 |
|---|---|---|
| 1 | 친숙한 대상 | 설명 없이 이름만 대도 아는가? |
| 2 | **상식적 해법이 실제로 실패** | "그냥 ~하면 되잖아"가 왜 안 되는지 **물리적 이유**가 있는가? |
| 3 | **실제 해법이 직관에 반함** | "~ 대신 ~한다" 한 줄이 나오는가? |

### 가점
수치 증명 가능 · **지금도 작동 중** · 일상 단위 환산 가능(아파트 N층 / 축구장 N개)

### ⛔ 실격
- **"만약 당신이 ~라면"** 가정형 — 검증된 실패 포맷
- **how-to 레시피** — 갈등 구조 없음
- 반전 없음 / 상식적 해법이 실제로 통함

**게이트 통과분만 STEP 2로.** 통과 못 하면 소재를 바꾼다.

## STEP 2 — 팩트체크 ★가장 오래 걸린다

이 장르의 신뢰는 **수치**에서 나온다.

- 모든 수치는 **1차 출처** (공공기관 보고서·공시·논문·표준·특허)
- **출처 없는 수치는 쓰지 않는다.** 2차 출처만 나오면 **정성적 표현으로 대체**
- ★**확정된 사실 / 논쟁 중인 해석 / 영상적 단순화**를 스스로 구분해 표시한다.
  단순화한 것은 설명글에 고지한다(STEP 9). **거짓 정밀도를 만들지 않는다**
- 대본에 `[근거: URL]` 주석을 남기고 렌더 전 제거
- 계산으로 나온 값은 **보수적으로 낮춰** 표기 (예: 1,700배 → "천 배 넘게")

★ 과장 쪽으로 틀리면 채널이 죽는다. 축소 쪽으로 틀린다.

## STEP 3 — 대본 (95초 · **약 650자**)

### ★대본 전에 네 문장을 먼저 정한다

1. **핵심 질문** — 끝까지 알고 싶어질 공학적 미스터리
2. **핵심 메커니즘** — 문제를 푸는 구조·장치·물리 작용
3. **화면에서 보이게 만들 흐름** — 공기 / 물 / 흙 / 열 / 압력 / 하중 / 진동 / 에너지 중 하나
4. **이 대상만의 차별점**

3번이 특히 중요하다 — **보이는 흐름이 정해져야 STEP 6b 의 그래픽이 정해진다.**
"보여줄 흐름이 없다"면 소재 게이트로 돌아간다.

### 8구간 비율 계약

| # | 구간 | % | 초 | 내용 |
|---|---|---|---|---|
| 1 | 훅 | 9 | 0~9 | 모순 → 정체 공개 → **인공/의도 선언** |
| 2 | 문제 | 15 | 9~23 | 원래 어땠는지, 뭐가 문제인지 |
| 3 | 1차 해법 | 16 | 23~38 | **수치 폭격** |
| 4 | **새 문제** | 15 | 38~52 | "그런데 ~했더니 이번엔" |
| 5 | **반박 선점** | 6 | 52~58 | "그럼 ~하면 되지 않냐고요?" + 즉답 |
| 6 | **발상 전환** | 10 | 58~68 | 핵심 명제 한 줄 |
| 7 | 작동 원리 | 14 | 68~81 | 메커니즘 + 수치 |
| 8 | 클로징 | 15 | 81~95 | **현실적 대가·한계** 한 줄 → 현재 연결 + 수미상관 |

### 고정 문형 4종 (채워 쓴다)

```
훅      : "여기 {장소}에는 {A}인데 {A가 아닌} {대상}이 있습니다."
          "…{정체}죠. 그런데 이건 {저절로 그런 게} 아니라 {인공/의도}입니다."
반박선점: "그럼 {상식적 해법}하면 되지 않냐고요?"  "{그러면 벌어지는 일}."
전환    : "그래서 발상을 뒤집습니다. {상식} 말고 {역발상}한 겁니다."
클로징  : "우리가 아는 그 {대상}은 이렇게 {만들어진} 겁니다."
```

### 엔진 = 문제 → 해법 → **새 문제** → 해법 사슬
각 해법이 새 문제를 낳게 짠다. 최소 1회, 길면 2회.

### 문체
- 구어체 존댓말 — `~거든요` `~죠` `~고요` `~습니다`
- **짧은 단문.** 복문 금지
- 수치는 **일상 단위 병기**
- 반박 선점 편당 1~2회
- ★**분량 = 650자 내외**.
  ⚠️ 초기에 450~550자로 잡았다가 **28% 얇아 휑했다.** 이 장르는 쉼이 거의 없다 —
  "주변 설명"(배경·맥락·부연)으로 채운다
- ⚠️ **자/초는 화자마다 다르다.** 6.8자/초는 **벤치마크 채널 화자** 값이고,
  우리 fish.audio 클론(speed 1.1)은 **8.9자/초**다(2026-08-20 실측, 719자→80.45초).
  그래서 **초 단위 목표를 자 수로 역산하지 않는다** — 자 수로 쓰고 TTS 로 실측한다.
  ★비율 계약은 총 길이가 줄어도 그대로 유지된다(실측에서 8구간 전부 ±1.5%p 안)

## STEP 4 — 제목 (6패턴 중 택1)

| 패턴 | 틀 |
|---|---|
| A인데 A가 아니다 | `{대상}이 {A}가 아니라 {B}인 이유` |
| 사실은 ~ 위에 | `{대상}, 사실은 {반전} 위에 있습니다` |
| 보이는 것 ≠ 실제 | `{대상}은 {A}해 보이지만 사실 {A}하지 않습니다` |
| **일부러** | `{대상}을 일부러 {비상식적 처리}한 이유` |
| 진짜 이유 | `{상식적 조치}해도 {문제}가 안 잡히는 진짜 이유` |
| 모순 수치 | `{조건A}인데 {모순되는 사실B}` |

**필수**: 구체 수치 · 친숙한 고유명사 · `~인 이유` / `~한 방법` 어미

## STEP 5 — 장면표 ★"딱 봐도 이해"가 전부다

### ★TTS 를 먼저 만든다 — 추정 길이로 장면표를 짜지 않는다

대본 승인 → **나레이션 wav 부터 생성** → `ffprobe` 로 실제 초를 잰다.
그 실측 초가 클립 수를 결정한다. 추정 95초로 짜놓고 TTS 가 108초로 나오면 장면표가 통째로 밀린다.

| 실측 길이 | 원본 클립 수 |
|---|---|
| 55~70초 | 16~22개 |
| **90~110초** | **26~36개** |

이건 출발점일 뿐 — **대본에 실제로 등장하는 물리 상태의 개수**가 우선한다.

### 클립 리듬 = 원본 5초, 편집에서 1.5~4초

한 클립이 **2~4초 화면을 책임진다**. 1초 난사가 아니다 —
그래픽이 조립되는 걸 보여주려면 그만한 시간이 필요하다.

| 구간 성격 | 편집 후 길이 |
|---|---|
| 문제 제기·전환 | 1.5~3초 |
| 핵심 메커니즘·보상 | 3~4초 |
| 그래픽 조립이 늦게 끝나는 컷 | 필요한 만큼 유지 |
| 의미가 겹치는 카메라 무브 | 과감히 잘라낸다 |

⚠️ **원본 총합 ≠ 완성 길이.** 30클립×5초=150초 원본으로 100초를 만든다. 편집에서 50초를 버리는 게 정상이다.

### ★ID 는 대본–CLEAN–INFO–클립을 1:1로 묶는다

```
장면 S01A · 키프레임 KF-01A · 클립 CLIP01

01_S01A_KF-01A_CLEAN_spillway-wide.png
01_S01A_KF-01A_INFO_spillway-wide.png
01_CLIP_S01A_KF-01A_spillway-wide.mp4
```

- 파일명 앞 **0 채운 번호 = 대본 순서**. 이름 오름차순이 곧 타임라인 순서가 되게 한다
- 대응표는 `manifests/IMAGE_SEQUENCE.md` 에 저장
- ⚠️ **파일명·생성시각을 믿지 말고 실제 화면을 보고 매핑한다.** 생성 도구는 순서를 섞어서 뱉는다
- ⛔ **ID 문자열을 이미지 프롬프트에 넣지 말 것** — 레퍼런스 쇼츠는 `S04A_KF-04A_CLEAN_V2_LEVEL_FLIGHT`
  가 화면 좌하단에 그대로 찍혀 나왔다. ID 는 파일명에만 쓴다

### 동기화 하드 규칙 5 (어기면 리테이크)

| # | 규칙 |
|---|---|
| 1 | **1컷 = 1개념** |
| 2 | **말하는 명사는 그 순간 화면에서 하이라이트** |
| 3 | **수치를 말하면 그 수치가 화면에** — 말로만 지나가는 숫자 금지 |
| 4 | **비교는 반드시 병치** — 9:16 은 **상하 분할**로 동시에. 순차는 대비가 죽는다 |
| 5 | **부정은 X 표시로 즉시 시각화** |

### 장면마다 명시할 것

`S ID / KF ID / 초 / 나레이션 원문 / 장면 목적 / CLEAN 내용 / INFO 핵심 / 카메라 무브`

핵심 장면엔 **왜 이 화면인가** 한 줄을 붙인다. 전부 `manifests/IMAGE_SEQUENCE.md` 에 남긴다.

### ★밀도는 그래픽에 몰고, 글자는 줄인다

두 벤치마크가 겉보기엔 반대로 말하는데 실은 층이 다르다.

| 층 | 밀도 | 근거 |
|---|---|---|
| **그래픽**(유선·화살표·치수선·앵커·발광) | **클립당 2~3개** | 파일럿 v1 은 0.92개로 만들었다가 화면이 휑했다 |
| **글자**(한글 라벨·수치) | **작은 라벨 1~3개 + 수치 0~1개** | 설명은 나레이션이 한다. 화면이 나레이션을 받아 적으면 둘 다 죽는다 |

⛔ **나레이션을 그대로 옮긴 큰 헤드라인 금지.** 화면의 주인공은 글자가 아니라
**흐름·파면·하중 경로**다. 결론 컷에서만 중간 크기 문구 한 줄을 허용한다.

### ⛔그래프는 "비교 대상"이 없으면 의미 없는 박스가 된다

파일럿에서 태운 것 — 두께 프로파일을 **선 하나**로 그렸더니
평평한 구간에선 그냥 **의미 없는 검은 막대**로 보였다. 정보가 없으니까.

고친 방법 3단:

| # | 조치 |
|---|---|
| 1 | **선 → 면.** 곡선 아래를 채워 "두께 단면"으로 읽히게 |
| 2 | **패널 + 축 라벨.** 어두운 패널로 피사체와 분리하고 `두께` 축 표기. 피사체 위에 겹치면 정체불명이 된다 |
| 3 | ★**유령 비교 곡선.** 이상적 형태를 **흰 점선**으로 겹친다 — "이래야 하는데 이렇다"가 한눈에 보인다 |

**원칙: 값 하나만 그린 그래프는 그래프가 아니다.** 반드시 비교 대상(이전 상태·이상적 형태·기준선)을 같은 화면에 둔다.

### 핵심 시각 장치를 3개 설계한다
편마다 "이것만 되면 산다"는 컷 3개를 지정한다. 보통:
1. **왜 어려운가의 증명** (겹치는 구간·모순 수치)
2. **딜레마** (상하 분할 + 양쪽 X 동시 표시)
3. **역발상의 시각 증명** ← 심장. 앞에서 심어둔 그래프/도형이 뒤집히는 컷

  (파일럿 만두 편의 클레이 룩은 그 편 한정 유산)
- **깊이가 있어야 한다** — 뒤에 5~15도 카메라 무브를 걸어야 하므로 전경/중경/배경이 분리돼야 함

- ⛔ **글자·숫자·화살표·차트·UI 를 CLEAN 에 절대 넣지 않는다.** 그건 INFO 담당
- 네온·판타지 에너지 금지. 역사적·기계적 오류 억제
- **같은 시드**로 전 컷을 뽑아 룩을 통일

### ★장면 계열을 갈아끼운다 — 각도만 다른 중복 금지

같은 대상을 각도만 바꿔 나열하면 클립 수만 늘고 지겨워진다.
**새 물리 상태 · 하중 경로 · 시공 단계 · 내부 단면 · 매크로 · 규모 비교 · 강한 전환**
중 하나가 바뀔 때만 새 장면을 만든다.

| 계열 | 내용 |
|---|---|
| **완성체** | 대상 3/4 뷰 (훅·클로징) |
| **단면** | 컷어웨이 — 내부 구조가 재료별로 구분 |
| **부위 확대** | 핵심 부위 / 해법 부위 |
| **재료 매크로** | 내부 재료만 화면 가득 |
| **상태 변화** | 하중·온도·수분이 다른 같은 대상 |
| **환경** | 작동 환경 (조리·물속·지하·상공) |
| **공정** | 사람 손·기계가 만드는 장면 |
| **실패체** | 터짐·붕괴·균열 |
| **규모 비교** | 사람·차량·건물과 나란히 |

★ **실패체가 특히 중요하다.** "이러면 안 된다"를 X 표시로만 때우지 말고 **실제 실패한 그림**을 보여준다.

⚠️ **재료 이름만 쓰면 모델이 다르게 알아듣는다.** `frost` 만 넣었더니 서리가 아니라
**금속 광택**으로 두 번 연속 그렸다(2026-08-20). `hoarfrost` · `snow-like ice crystals` ·
`buried under a thick white blanket` 처럼 **형태와 질감을 같이 적어야** 나온다.
같은 실패를 `defrost heater` 에서도 겪었다 — `glowing hot amber orange along its whole length` 를
붙이기 전엔 그냥 파이프만 그렸다.

⚠️ **한 이미지 안에 대상이 중복돼 보이면 안 된다** — 피 단면인데 두 장이 겹쳐 보이면
"피가 원래 두 겹인가?" 하는 오해를 만든다. **단일 객체는 `one` / `single` / `nothing else in frame`** 으로 강제.

## STEP 6b — INFO 이미지 (같은 구도 + 계측 그래픽)

INFO 는 **새 그림이 아니라 CLEAN 의 목표 상태**다. 카메라·크롭·형상·조명·재료·배경이
CLEAN 과 **픽셀 단위로 같아야** 한다 — 다음 단계에서 이 둘 사이를 보간하기 때문이다.

### ★INFO 는 생성하지 말고 합성한다 (2026-08-20 실측)

CLEAN 을 참조로 넣고 "구도 유지한 채 그래픽만 얹어라"를 **생성모델에 시켰다가 장면이 통째로 날아갔다.**
`krea2_ref.py` 는 편집기가 아니라 **스타일 앵커**(style-reference LoRA + Kontext multi-reference)라
구도를 보존하지 않는다. 110초 태우고 노이즈 위에 선만 남은 이미지가 나왔다.

**따라서 INFO = CLEAN 위에 우리가 벡터를 직접 얹어 만든다.** 구도 보존이 100% 보장되고,
그래픽 위치를 우리가 정확히 지배한다.

- ⛔ **INFO 에도 글자·숫자를 넣지 않는다.** 다음 단계 생성모델이 글자를 뭉갠다.
  한글은 STEP 8 에서 완성된 클립 위에 얹는다
- 요소를 **분리해 둔다** — 앵커 → 선 → 화살촉 → 발광 순으로 조립될 수 있게

### ★좌표는 격자를 씌워 읽는다 — 눈대중하면 앵커가 피사체를 벗어난다

CLEAN 위에 10% 간격 격자를 그린 콘택트 시트를 만들어 놓고 좌표를 읽는다.
눈대중으로 잡은 한 컷이 **앵커가 냉장고가 아니라 위쪽 벽에 떴고**, 클립을 다 뽑고 나서야 발견했다
(2026-08-20, 재생성 1회). 격자를 씌운 나머지 29컷은 전부 제자리였다.

```python
# CLEAN 여러 장 + 10% 격자 → 한 장으로 붙여 좌표 읽기
for g in range(10, 100, 10): d.line(...); d.text((x+2, 2), str(g))
```

피사체 위에 맨 글자를 얹으면 묻힌다.

### ★텍스트도 "그려져야" 한다 (모션)

툭 나타나면 싸구려로 보인다. **칩은 슬라이드하고, 숫자는 오버슈트하고, 바는 차오른다.**

| 훅 | 용도 | 이징 |
|---|---|---|
| `useDraw` | 지시선·게이지 바 — **쭉 뻗는다** | easeOutCubic, 14~18f |
| `usePop` | 라벨 칩·치수 숫자 — 살짝 오버슈트 | bezier(.16,1.2,.3,1), 12f |
| `useIn` | 단순 페이드 | 선형 |

**순서가 중요하다** — 지시선이 먼저 뻗고(0f), 칩은 절반쯤에서 따라 나온다(+7f).
동시에 나타나면 "그려지는" 느낌이 안 산다. RedX 는 두 획을 순차로 긋는다.

⚠️ **클립 안에서 그래픽이 조립되는 타이밍과 어긋나면 안 된다.**
클립이 1.7초에 지시선을 다 그렸는데 Remotion 라벨이 0.3초에 떠 있으면 순서가 뒤집힌다.
텍스트는 **해당 그래픽이 완성된 뒤**에 붙인다.

### ★라벨은 "선 → 타이핑" 2단으로 나온다

지시선이 먼저 그어지고(0f), **글자는 한 자씩 찍힌다**(+8f, `useType` 34~40cps).
미완 상태엔 커서 `_` 를 붙인다. 통째로 페이드인하면 계측 장비 느낌이 안 난다.

★ **영문 라벨 = 권위 / 한글 라벨 = 이해**. 이 이중 구조가 시그니처다.
★ 부품은 **1회 제작 후 전 회차 재사용**. 파일럿 비용 = 라인 전체 초기 투자.

| **그래프 위치** | `ThicknessProfile` 기본 y=52. 자막(78%)과 겹치면 둘 다 죽는다. **캡션은 그래프 위**로 |

| **좌표 재계산** | 클립은 카메라가 움직인다. **정지 이미지 시절의 퍼센트 좌표를 그대로 쓰면 라벨이 피사체를 놓친다.** 라벨은 카메라가 멎는 후반부(3.4초 이후 구간)에 붙이거나, 클립에서 프레임을 뽑아 좌표를 다시 잰다 |
| ⛔**`WebkitTextStroke` 금지** | 테두리를 획 **경계 중앙**에 그려서 안쪽을 파먹는다. 한글은 이것만으로 뭉개진다. `paintOrder: "stroke fill"` + 다중 `textShadow` 로 대체 |
| ★**자막은 항상 한 줄** | 줄 수가 컷마다 바뀌면 자막 덩어리의 **세로 기준선이 출렁여** 읽는 눈이 끊긴다(2026-08-20 사용자 지시). 줄바꿈 대신 **폭에 맞춰 글자 크기를 줄이고**(`SUB_AVAIL / subEm(text)`), 한 줄에 안 들어가는 문장은 **시간으로 쪼개** 컷 안에서 순차 재생한다(`sub` 를 배열로) |
| ⛔**균형만 보고 쪼개지 말 것** | 글자 수만 맞추면 `천 / 분의 일`·`되지 / 않냐고요`·`밀어 / 넣으니` 처럼 **한 덩어리를 가른다**(실측). 후보 경계마다 점수를 매겨 고른다 — 쉼표·물음표 뒤(−8) · 연결어미 뒤(−3) · 조사 뒤(−1) / 관형사·수사 뒤(+14) · 의존명사·보조용언 앞(+14) |
| **자막 크기** | 1080 폭 기준 **최대 54px / weight 800**, 자동 축소 하한 45px 선. 46px 이하는 폰에서 흐리다 |
| **영문 라벨** | **30px + 빨강 칩 배경**. 24px 는 안 읽힌다 |
| **게이지 제목** | 빨강 글자만 두면 배경에 묻힌다 — **어두운 칩을 깔아** 대비 확보 |
| **라벨 화면이탈** | 앵커만 클램프하면 **긴 라벨은 여전히 잘린다.** 칩 폭까지 계산해야 한다 — 30px 기준 `글자수 × 2.25% + 5%`. 그리고 **영문 라벨은 12자 이내로 축약**(`HEAT INGRESS`→`HEAT IN`) |
| **게이지 가독성** | 피사체 위에 얹으면 묻힌다. **불투명 패널(0.9)** 을 깔고 **하단 여백(y 48~62)** 으로 내린다 |
| **클립 배선** | `Cut.clip`(public 상대경로) + `clipFrom`(초) → `OffthreadVideo`. **`muted` 필수**(H3 오디오 버림). 한 클립을 구간 나눠 2컷에 쓸 수 있다 |
| ★**clipFrom 은 뒤에서 잡는다** | 조립은 원본 **0.4~3.4초**에 일어난다. 컷이 2.5초인데 `clipFrom=0` 으로 쓰면 **조립이 덜 끝난 채 잘린다.** `clipFrom = max(0, 4.6 − 컷길이)` 로 잡아 **끝을 4.6초에 맞추면** 모든 컷이 완성된 상태로 끝난다. 오프닝 1~2컷만 0 에서 시작해 빈 화면 도입을 살린다 |
| **텍스트 delay** | 클립 안 그래픽이 다 그려진 뒤(≈24프레임)에 라벨을 붙인다. 영문 라벨은 타이핑까지 있어 `delay+8` 부터 글자가 보이기 시작한다 — 2초 미만 컷에는 영문 라벨을 걸지 않는다 |
| **치수 라벨 크기** | 40px/900. 34px 이하는 세로 화면에서 안 읽힌다 |

### ★내레이터 보이스 잠금 (회차 간 일관성)

규격 = `knowledge/30-playbooks/voice-profile-bible.md`

3화 목소리가 1화와 다르면 채널이 무너진다.

| 잠글 것 | 방법 |
|---|---|
| 엔진·화자·속도·피치 | 채널 설정에 못박고 전 회차 동일. **회차마다 고르지 않는다** |
| 클론 ref wav | **채널 자산으로 고정.** 회차마다 재녹음 금지 |
| 발음 | 공학 용어·수치 읽기를 `config/pronunciation-dict.json`에 축적 |
| 볼륨 | `LOUDNORM_TTS` 정규화로 회차 간 편차 제거 |

**내레이터 프로필도 텍스트로 1회 확정해 버전 태그를 붙인다** (`@voice_NARR_v1`).
7요소(나이·성별·국적/언어·음역대·질감·속도·말투 캐릭터)를 채우되,
⚠️ 드라마와 달리 **"TTS 내레이터 톤 금지"는 여기선 쓰지 않는다** — 그 톤이 정답이다.
대신 **"낭독체 금지 / 구어체 유지"**로 바꿔 잠근다.

**회차 간 QA**: 신규 회차 나레이션을 **직전 회차와 나란히 들어본다.** 톤이 튀면 재생성.

### 조립

★나레이션 wav 는 **STEP 5 이전에 이미 만들어져 있다.** 여기서 새로 만들지 않는다.

편집 순서를 지킨다 — 뒤집으면 앞 단계를 다시 한다.

```
나레이션 배치 → 클립 길이 조정(1.5~4초로 트림) → 핵심 효과음
→ BGM → 한글 라벨·자막 → 음량·색 정리 → 무음 테스트
```

- 믹스: **대사 -6dB / BGM -12~-15dB**. 컷별 BGM 금지, 완성본 위에 한 곡 통으로
- H3 클립의 자체 오디오는 **버린다**(`muted`)
- 출력: **1080×1920 · H.264 · AAC 48kHz · 5,000~10,000 kbps**

### ★무음 테스트 게이트 (발행 전 필수)
**소리와 자막을 끄고 재생.** 흐름이 읽히면 통과, 아니면 그 구간 재작성.

### 설명글
```
1. 제목 재진술  2. 배경("원래 ~였습니다")  3. 문제("그런데 ~")
4. 해법 반전("~ 대신 ~")  5. 수치 나열
6. ★이해를 돕기 위해 일부 현상을 단순화했습니다. (한 줄 고지)
7. ★반박·정정 환영합니다. 근거 자료와 함께 댓글로 남겨주세요.
8. 해시태그 #지식채널 + 소재 태그
```
6번은 **화면의 그래픽이 실제 시뮬레이션이 아니라는 방어선**이다. 공학 시청자는 이걸 짚는다.
7번은 신뢰 장치이자 댓글 유발 장치 (벤치마크 댓글 800~1000편대).

### 롱폼 재활용
히트한 쇼츠를 **5분 확장**. 벤치마크가 실제로 쓰는 방식 — 구조는 같고 각 구간을 늘린다.
